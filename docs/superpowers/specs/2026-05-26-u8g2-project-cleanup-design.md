# U8G2 Project Cleanup Design

## Goal

Clean up the STM32CubeIDE project structure without changing application behavior. The project should keep only the U8G2/U8X8 files needed for the current SSD1306 128x64 I2C OLED build in the active build tree, move unused U8G2/U8X8 files out of the build path, and stop tracking generated build artifacts.

## Current Context

- Application code in `Core/Src/main.c` uses `u8g2_Setup_ssd1306_i2c_128x64_noname_f()`.
- U8G2 depends on the U8X8 lower-level display and byte/gpio callback layer, so `u8x8_*` cannot be removed wholesale.
- The repository currently mixes project application files and many U8G2/U8X8 library files under `Core/Src` and `Core/Inc`.
- `Debug/` and `Release/` contain generated build outputs and should not be treated as source.
- The worktree already contains unrelated modifications in application source and generated build outputs; cleanup must avoid reverting them.

## Recommended Structure

- Move active U8G2/U8X8 source files to `Middlewares/Third_Party/u8g2/src/`.
- Move active U8G2/U8X8 headers to `Middlewares/Third_Party/u8g2/include/`.
- Move unused U8G2/U8X8 source files to `archive/u8g2-unused/`, outside CubeIDE's normal source build path.
- Leave project-owned application files in `Core/Src` and `Core/Inc`.
- Keep FatFs in its existing `Middlewares/Third_Party/FatFs` location.

## Active File Selection

The active U8G2 set should be derived from the current OLED path:

- `u8g2_Setup_ssd1306_i2c_128x64_noname_f`
- `u8x8_d_ssd1306_128x64_noname`
- `u8x8_cad_ssd13xx_fast_i2c`
- U8G2 drawing, buffer, font, setup, and memory helpers used by `main.c`
- U8X8 byte, display, CAD, string/number helpers, and header definitions needed by U8G2

Files for unrelated display controllers and unused U8X8 widgets should move to `archive/u8g2-unused/`.

## Build Configuration

- Update `.cproject` or CubeIDE source entries so only `Middlewares/Third_Party/u8g2/src/` is compiled for the active U8G2 set.
- Add `Middlewares/Third_Party/u8g2/include/` to include paths.
- Remove stale `Core/Src/u8g2_*` and `Core/Src/u8x8_*` build entries after files move.
- Do not hand-edit generated `Debug/Core/Src/subdir.mk` as the source of truth; it may be regenerated by CubeIDE.

## Generated Artifacts

- Add or confirm `.gitignore` entries for `Debug/`, `Release/`, object files, dependency files, maps, lists, and other generated outputs.
- Do not delete user source changes.
- Remove tracked generated artifacts only if they are confirmed as build outputs and not required source inputs.

## Error Handling

- If a moved file causes an include failure, prefer fixing include paths over changing application code.
- If linking reports an undefined U8G2/U8X8 symbol, move the required dependency back into the active U8G2 source set.
- If CubeIDE regenerates project metadata, keep the generated change only when it matches the intended source/include layout.

## Verification

- Run a clean build if the local ARM toolchain is available.
- Confirm there are no missing include errors.
- Confirm there are no U8G2/U8X8 undefined references.
- Confirm `Core/Src/main.c` behavior remains unchanged except for any minimal include path adaptation if required.
- Review `git status` to ensure only intended cleanup files are changed.

## Non-Goals

- Do not rewrite OLED drawing logic.
- Do not replace U8G2 with another OLED library.
- Do not remove all U8X8 files blindly.
- Do not optimize firmware behavior beyond build-tree and project-structure cleanup.
